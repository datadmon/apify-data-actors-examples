# MCP Registry entries, one per actor

Each folder holds a `server.json` for the [official MCP Registry](https://registry.modelcontextprotocol.io/). The entry is a *remote-only* server: it points at Apify's hosted MCP server filtered to a single actor, for example `https://mcp.apify.com/?tools=data_daemon/iimjobs-jobs-scraper`. These are discovery pointers, not new hosting. India Jobs MCP is the exception: its manifest points directly to its five-tool Standby MCP endpoint; connections consume platform usage.

Any MCP client that reads the registry (Glama imports it automatically, PulseMCP imports when it reopens submissions) can then find, for example, "IIMJobs Jobs Scraper (Apify)" and connect with an Apify API token in the `Authorization: Bearer <token>` header. A free token is at https://console.apify.com/account/integrations.

## Use one directly (no registry needed)

Claude Desktop / Cursor / VS Code: add a remote MCP server with the URL from the `server.json` and the `Authorization` header. The same URL works for several actors at once: `https://mcp.apify.com/?tools=data_daemon/iimjobs-jobs-scraper,data_daemon/hirist-jobs-scraper`.

## India Jobs MCP and authenticated discovery

[Tested Claude Desktop/Code, Cursor and Gemini CLI snippets](india-jobs-mcp/README.md) include a protocol checker and
the IIMJobs Glama diagnosis. Both the direct Standby endpoint and filtered Apify MCP Actor tools require a user's token
even for initialization/tool discovery. An anonymous 401 does not establish a scraper outage.

## Publish the six R1 candidates (repository owner only)

The namespace `io.github.datadmon/*` requires GitHub device login as `datadmon`. The script validates the three new
entries (India Jobs MCP, India Jobs Feed, Naukri) and three updated descriptions (IIMJobs, IPO, Gazette), authenticates once,
publishes immediately, and verifies each exact name/version/endpoint through the Registry API. Existing matching versions
are skipped. It does not publish every generated draft folder.

From the Daemon Data workspace on Windows:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\examples-repo\mcp\publish-reach.ps1
```

This single owner command uses the prepared workspace virtual environment. Enter the printed device code at
GitHub's device login page as `datadmon`. Registry JWTs expire quickly; the script publishes in the same session.
Standalone users can `pip install jsonschema` and place `mcp-publisher` on PATH (or pass `-Publisher <binary-path>`).
Use `-ValidateOnly` for an uncharged, unpublished validation; `-UseExistingLogin` skips device login if already authorized.

The checked-in binary advertises `validate` in help but returns `Unknown command: validate`; `validate_manifests.py`
therefore validates against the official JSON schema. Publishing needs the owner: the saved Registry JWT returned HTTP 401
(`Invalid or expired Registry JWT token`) on November 6, so no new entry was published in this implementation session.

Check the namespace: [Registry API](https://registry.modelcontextprotocol.io/v0/servers?search=io.github.datadmon&limit=100).
The per-actor manifests are generated by `scripts/build_examples_repo.py` in the publisher workspace. Bump `version`
before publishing a changed entry; Registry versions are immutable.
