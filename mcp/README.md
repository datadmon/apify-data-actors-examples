# MCP Registry entries, one per actor

Each folder holds a `server.json` for the [official MCP Registry](https://registry.modelcontextprotocol.io/). The entry is a *remote-only* server: it points at Apify's hosted MCP server filtered to a single actor, for example `https://mcp.apify.com/?tools=data_daemon/iimjobs-jobs-scraper`. Nothing runs here; the actor itself is unchanged (no Standby mode, so agentic payments stay available).

Any MCP client that reads the registry (Glama imports it automatically, PulseMCP imports when it reopens submissions) can then find, for example, "IIMJobs Jobs Scraper (Apify)" and connect with an Apify API token in the `Authorization: Bearer <token>` header. A free token is at https://console.apify.com/account/integrations.

## Use one directly (no registry needed)

Claude Desktop / Cursor / VS Code: add a remote MCP server with the URL from the `server.json` and the `Authorization` header. The same URL works for several actors at once: `https://mcp.apify.com/?tools=data_daemon/iimjobs-jobs-scraper,data_daemon/hirist-jobs-scraper`.

## Publishing (repository owner only)

The registry namespace `io.github.datadmon/*` requires a GitHub login as the repository owner, so publishing is a manual, interactive step:

```bash
# once: https://github.com/modelcontextprotocol/registry/releases (mcp-publisher binary)
mcp-publisher login github            # device-code flow, log in as datadmon
for d in mcp/*/; do (cd "$d" && mcp-publisher publish); done
```

Check an entry afterwards: `https://registry.modelcontextprotocol.io/v0/servers?search=<actor-name>`.

The files are generated by `scripts/build_examples_repo.py` in the publisher's workspace; edit the actor table there rather than the JSON by hand. Bump `version` when a description changes (the registry keeps every version).
